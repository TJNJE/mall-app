## Findings

### F1-已修复-中-ErrorBoundary 捕获的渲染错误未上报 Sentry，线上渲染崩溃不可见

- **入口/函数**: `ErrorBoundary` 的错误捕获
- **文件(行号)**: `src/common/components/ErrorBoundary.tsx`（fix 后新增 `componentDidCatch`）
- **输入场景**: 任意页面组件在渲染阶段抛错
- **实际分支**: 原仅有 `getDerivedStateFromError`，错误被兜底 UI 吞掉，无任何上报
- **预期行为**: 渲染错误同样应进入监控
- **实际行为**: Sentry 只自动捕获未被错误边界处理的异常，被 ErrorBoundary 吞掉的渲染错误不会上报——最严重的崩溃类型恰好无监控记录
- **直接证据**: 原文件中无 `Sentry.captureException` / `logger.error` 调用
- **影响**: 可观测性缺口，与 S4 建立监控的目标直接冲突
- **建议改法和验证点**: 在错误捕获处调用 `logger.error(...)`
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
- **fix 验证**: 已新增 `componentDidCatch(error, info)` 调用 `logger.error`；`npm run build` / `lint` / `test` 均通过
