### F1-未修复-中-S1 未交付 plan 要求的 React Compiler 启用（plan deviation）

- **入口/函数**: Vite 构建配置 `plugins`
- **文件(行号)**: `vite.config.ts:8-10`
- **输入场景**: 执行 `npm run build` 生产构建
- **实际分支**: 插件数组仅 `react()` + `tailwindcss()`，无任何 React Compiler 配置
- **预期行为**: 依 `docs/gateflow/eng-gaps-phase2-plan.md` S1 success signal，「`npm run build` 在启用 React Compiler 后无报错」
- **实际行为**: React Compiler 未启用；仅保留注释说明 deferred 原因
- **直接证据**: `@vitejs/plugin-react` v6.0.2 的 `Options` 类型（`node_modules/@vitejs/plugin-react/dist/index.d.ts:8-41`）仅含 `include` / `exclude` / `jsxImportSource` / `jsxRuntime` / `reactRefreshHost`，不含 `reactCompiler` 或 `babel`；React Compiler 由独立导出 `reactCompilerPreset()` 提供，且需配合 `@rolldown/plugin-babel`（`package.json` 的 `peerDependenciesMeta` 中标记为 optional，当前未安装）
- **影响**: plan 目标未完全达成（编译期自动 memo 缺失）；但手动 `memo` + 稳定 `onOpen` 已覆盖本 slice 主要重渲染场景，功能无缺陷
- **建议改法和验证点**: 安装 `@rolldown/plugin-babel` 并按 `reactCompilerPreset()` 配置后重跑 `npm run build`；或由 controller 明确接受 deferred，并更新 plan / control_doc 的 S1 success signal
- **修复风险（低/中/高）**: 中（需额外依赖与 API 验证）
- **严重程度（低/中/高/严重）**: 中

### F2-未修复-低-hover 预取无防抖，快速滑过列表会触发 N 个详情请求

- **入口/函数**: `ProductCard` 的 `onMouseEnter`
- **文件(行号)**: `src/features/product/features/pages/ProductListPage.tsx:27-32`
- **输入场景**: 用户鼠标快速滑过商品网格（每页 8 个卡片）
- **实际分支**: 每次 `onMouseEnter` 直接调用 `queryClient.prefetchQuery`
- **预期行为**: 预取应限流，避免对不会进入的卡片产生无意义请求
- **实际行为**: 首次滑过 8 个卡片即触发 8 个详情请求；`staleTime: 10min`（`useProductDetail.ts:15`）仅能阻止重复 hover 同一卡片，不能阻止首次批量触发
- **直接证据**: `ProductListPage.tsx:27-32` 的 `onMouseEnter` 无任何 debounce / throttle / viewport 判定
- **影响**: 网络放大（弱网与移动端浪费流量），与「预取提速」的收益存在 tradeoff
- **建议改法和验证点**: 加 100-200ms 防抖，或改为元素进入视口（`IntersectionObserver`）后才预取；验证点：滑过列表时 Network 面板请求数显著低于卡片数
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低（属 plan 已接受的预取设计 tradeoff，但可优化）
