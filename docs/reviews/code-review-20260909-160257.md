## Findings

### F1-未修复-低-生产产物包含仅 DEV 使用的 mockServiceWorker.js

- **入口/函数**: Vite 静态资源复制（`public/` → `dist/`）与 gzip 插件
- **文件(行号)**: `public/mockServiceWorker.js`；build 产物 `dist/mockServiceWorker.js(.gz)`
- **输入场景**: 执行 `npm run build`
- **实际分支**: MSW 的 service worker 仅在 `main.tsx` 的 `if (import.meta.env.DEV)` 分支注册，生产代码不使用
- **预期行为**: 生产产物不应包含开发专用文件
- **实际行为**: `mockServiceWorker.js` 及其 `.gz`（8.91 kB / gzip 2.94 kB）始终出现在 `dist` 中
- **直接证据**: `/tmp/build_s5b.log` 产物列表含 `mockServiceWorker.js.gz`；`main.tsx` 的 MSW 注册被 `import.meta.env.DEV` 守卫
- **影响**: 产物冗余（体积很小）；若该文件被部署到线上，存在暴露内部 mock 结构的信息面
- **建议改法和验证点**: 构建后删除（`vite-plugin-static-copy` 排除或 build 脚本 `&& rimraf dist/mockServiceWorker.js*`）；验证点：`ls dist/mockServiceWorker.js` 无产物
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
- **裁决**: deferred-with-owner（预存问题，非本 phase 引入；S2 压缩插件只是使其可见）

### F2-未修复-低-TypeScript 层的解包契约仍依赖双重断言维持

- **入口/函数**: axios response 拦截器
- **文件(行号)**: `src/lib/request.ts:43`（`return body.data as unknown as AxiosResponse`）与 `:54`（`instance as unknown as UnwrappedAxios`）
- **输入场景**: 所有 api 调用的类型检查
- **实际分支**: 运行时解包语义正确，但类型层靠两处 `as unknown as` 串联
- **预期行为**: 类型应无断言地描述「拦截器解包 → api 层拿到 T」
- **实际行为**: 断言链使 `UnwrappedAxios` 契约对编译器不可证
- **直接证据**: S1 为修 build 阻断引入第一处断言（Phase 1 遗留的 tsc 错误）；第二处为 Phase 1 Slice B 原有
- **影响**: 类型层安全性弱化；若后端响应形状变更，编译期无法提前暴露
- **建议改法和验证点**: 重构为「拦截器保持 AxiosResponse + 包装层统一解包」，消除断言；验证点：`npm run build` 通过且 api 层返回类型仍为解包后的 `T`
- **修复风险（低/中/高）**: 中（影响所有 api 调用点）
- **严重程度（低/中/高/严重）**: 低
- **裁决**: deferred-with-owner（Phase 1 遗留 + S1 必要修复的组合，运行时行为正确）
