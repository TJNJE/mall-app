## Findings

### F1-未修复-低-MSW handlers 未采用契约类型且响应缺 page/pageSize 字段

- **入口/函数**: `src/mock/handlers.ts` 的 `filterProducts`（返回 `{list,total}`）与 `paginateOrders`（返回 `{list,total}`）
- **文件(行号)**: `src/mock/handlers.ts:47,114-117`
- **输入场景**: 商品/订单列表请求
- **实际分支**: handler 组装 data 时未包含契约 required 的 `page`/`pageSize` 字段
- **预期行为**: 契约 required 字段应在响应中出现
- **实际行为**: 运行时响应缺这两个字段；但前端消费方均不读取 `data.page`/`data.pageSize`（分页由本地 state 管理），运行时无破坏
- **直接证据**: `handlers.ts:47` 返回类型仅 `{ list, total }`；契约 required [list, total, page, pageSize]
- **影响**: handlers↔契约一致性缺口（dev-only mock 层）；类型层无影响（handlers 未声明契约类型，消费方已由编译期保证）
- **建议改法和验证点**: handler 组装响应时补 `page`/`pageSize`；或 handlers 整体迁移为消费契约类型（后端联调期一并做）
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
- **裁决**: deferred-with-owner（dev-only mock；类型层真源已建立，运行时对齐留待 handlers 深化核对/后端联调）
